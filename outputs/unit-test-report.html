已验证的修复

  1. 任务停止与错误状态：在模型响应返回后、每次工具调用前、审批返回后及工具执行返回后复查状态；停止后不会继续执行后续工具、输出迟到的文本或推理内容，或把状态改回完成。
  2. 审批清理：批准、拒绝、超时、停止和任务收尾都会移除待审批记录并清除对应计时器；迟到的批准消息不会重复执行操作。
  3. 计划模式：工具分发层强制拦截工具调用，不再仅依赖提示词；计划模式不会请求修改审批或写入文件。
  4. 路径边界：创建多层新目录时解析最近的已存在祖先，阻止通过指向工作区外的符号链接写入；允许工作区内合法的链接及以两个点开头的普通子目录名。
  5. 递归读取边界：搜索中的文件和目录逐一接受真实路径校验，目录树遍历在读取子目录前再次校验；从子目录搜索时，仍允许工作区内其他目录的链接目标。完全访问模式保持其原有权限。
  6. 命令过滤：补齐递归删除参数的反向顺序、PowerShell 完整递归选项，以及高危进程递归命令的匹配。测试仅检查字符串和模拟调用，不运行危险命令。

生产修复集中在 modules/agent.js 与 modules/agent/tools.js。此外，package.json 新增测试入口；测试辅助代码修正了日志依赖注入，使异常分发用例能真正触发并验证错误处理。

测试文件与覆盖范围

  • test/agent-tools.test.js：只读权限、路径与符号链接、文件工具、递归读取、命令过滤和命令输出。

验证范围与现有边界

  • 本轮验证是隔离单元测试，未启动 Electron，也未执行真实模型接口、系统命令或图形界面端到端测试。
  • run_command 使用命令字符串过滤和执行目录设置，并未提供操作系统级文件访问沙箱。
  • 停止任务会抑制迟到响应及后续工具操作；当前实现没有主动中止在途 HTTP 请求，也不保证撤销已经开始的文件操作。
  • 现有边界尚保留：runAgent 初始化阶段读取配置异常会向调用方抛出；缺少 API Key 的提前返回不保存会话；续接任务没有重置空响应总结标志。这些不属于本轮已修复清单。

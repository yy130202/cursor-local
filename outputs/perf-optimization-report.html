逐项说明

1 · 会话记录改为增量渲染 收益最大

Agent 每输出一个工具调用或状态变更，renderTranscript() 都会清空整个 transcript 再重建所有 entry —— 包括重复的 Markdown 解析、事件重新绑定、LCS diff 重算。50 条消息的会话，一次事件就是 50 次重复构建。

// 改造前：每个非流式事件都整树重建
transcriptEl.innerHTML = '';
for (let i = 0; i < a.entries.length; i++) { /* 重建每个 entry */ }

// 改造后：签名一致就复用节点，仅变化的那一个重建
const sig = sigOf(en);                    // 覆盖该 entry 的全部可见状态
if (slot && slot.sig === sig && slot.node.isConnected) continue;
const built = buildEntryNode(en, isLast);
slot.node.parentNode.replaceChild(built.node, slot.node);  // 原地替换，不跳动
nodes[i] = { sig, node };

配套处理：思考指示器改为摘除—按需挂回，避免打断 entry 顺序；切换会话时才整体重建；头部文本与样式赋值加了值比较，挡掉无谓的样式重算。

2 · Agent 列表增量更新 + 解耦历史渲染

renderAgentList() 原本每次都重建全部列表项，末尾还无条件调用 renderHistory() —— 但历史会话列表与 agent 事件毫无关系，纯属白做功。

// 改造后：签名只含真正影响外观的四个字段
function agentItemSig(a) {
  return a.task + '\u0001' + a.cwd + '\u0001' + a.status + '\u0001'
       + (a.id === agentsState.selectedId ? '1' : '0');
}
// renderHistory 已从列表渲染中移除，改由 loadHistory / 筛选 / 删除等真实入口触发

3 · diff 记忆化 + 紧凑 DP 表

变更卡每次重建都要跑一遍 O(n·m) 的 LCS。改造后：内容未变的卡片直接命中缓存（容量 24，按插入顺序淘汰），DP 表从二维数组换成扁平 Int32Array，内存连续、分配更快。

中途我曾把回溯改成贪心对齐，那会让 diff 不再是最小编辑序列 —— 属于行为回归，已回退为原 DP 逻辑，只保留记忆化与内存布局优化。

4 · 文件树 git 标记 O(1) 化

原实现对每个目录项都遍历整张 git 状态表 (key === rel || key.startsWith(rel + '/'))。改为预计算「所有变更文件的祖先目录 Set」，查询变成 O(1)。缓存随 __gitStatusMap 实例更换自动失效。

function buildGitDirSet() {
  const map = window.__gitStatusMap;
  const set = new Set();
  for (const key of map.keys()) {
    let i = key.indexOf('/');
    while (i >= 0) { set.add(key.slice(0, i)); i = key.indexOf('/', i + 1); }
  }
  return set;
}

测试专门验证了前缀相似的边界：src/a.js 变更时，srclib、src2、s 都不应被误判为有变更。

5 · 目录读取去重

过滤模式下 dirHasMatch() 递归判定会读一遍目录，renderDir() 渲染时再读一遍。改为单次渲染内共享缓存，生命周期仅限一次 renderTree()，避免读到陈旧内容。

6 · git status 并行化 + 短 TTL 缓存

原本 git status 要串行等三个子进程。现在三者并行启动，并加 1200ms 短 TTL 缓存吸收同一波操作里的重复请求；同一 cwd 的并发请求共享同一个 in-flight promise，不会重复起进程。

const [st, nsU, nsS] = await Promise.all([
  runGit(cwd, ['status', '--porcelain', '-b']),
  numstatMap(cwd, false),
  numstatMap(cwd, true)
]);
缓存必须在任何写操作前失效，否则暂存后 1.2 秒内仍显示旧状态。stage / unstage / commit / checkout / pull / push / init / stageAll / unstageAll 共 9 处已全部接入 invalidateStatus()，并有测试断言「stage 后立刻读到新状态」。

7 · 全局搜索分块并发

原来是纯串行 walk，每个文件都 await stat + await readFile，磁盘 I/O 串行排队。改为「固定大小分块并发 + 块内按序提交」。

for (let start = 0; start < files.length && results.length < maxResults; start += CONC_GREP) {
  const chunk = files.slice(start, start + CONC_GREP);
  const chunkHits = await Promise.all(chunk.map(scanFile));  // 按 chunk 顺序返回
  for (const hits of chunkHits) {
    for (const h of hits) {
      if (results.length >= maxResults) return;
      results.push(h);
    }
  }
}
这里踩过一个真实缺陷：最初直接让并发任务 push 到共享数组，结果顺序取决于 I/O 完成先后（测试用「读延迟与文件名顺序相反」压测暴露），且 maxResults=500 被并发越界到 513。块内并发 + 块间串行 + Promise.all 保序 是同时满足速度与顺序的正确解法。

顺带修复的既有缺陷

Git 刷新后文件树从未重绘

renderer/git.js 刷新状态后调用 renderTree()，但判断写成了：

if (typeof renderTree === 'function') CL.editor.filetree.render();

而 renderTree 是 filetree.js 的模块内私有函数，从未挂到全局 —— 这个条件恒为 false，意味着 git 面板每次刷新后，文件树的变更着色从来没有生效过。已改为走已导出的模块接口：

CL.editor.filetree.render();
